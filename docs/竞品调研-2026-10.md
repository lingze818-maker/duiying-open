# 竞品调研：八家开源记忆系统 × 五问

> 2026-10 调研。数据来源：各仓库 README/docs 与 GitHub API（star 数为当日快照）。
> 目的：为"记忆上浮引擎"的设计提供参照——什么学得起，什么学不起，什么不该学。

## 我们的基线约束

- 纯本地：无向量库、无图数据库、无本地小模型、无 API key
- 零依赖：一个 Node 脚本 + 一个纯函数模块
- 哲学：**只浮线索，不替记忆**——检索结果不改写、不删除、不裁决任何记忆

---

## 1. Mem0（mem0ai/mem0 · ~67k★ · 活跃）

**写入**：旧版（v2，arXiv:2504.19413）LLM 两阶段——抽事实 + 与库内比对后裁决 ADD/UPDATE/DELETE/NOOP，原子单位是一句独立事实。**新版（v3）方向逆转**：单遍 ADD-only 只增不改，冲突消解推迟到检索时；实体抽取互链 + 时间感知检索。

**检索**：语义向量 + BM25 + 实体三路并行融合；top_k 注入 system prompt。

**遗忘**：v3 不删不改，靠检索排序近似"最新状态"。

**部署**：需 LLM API + 嵌入模型；混合检索需 spaCy 栈。**无法纯本地零服务**——但 BM25 与实体两路可零依赖手写。

**教训**：实测发现"LLM 裁决冲突再改写"成本高、易错，不如全部保留、检索时消解——与我们哲学殊途同归。

## 2. Letta（letta-ai/letta，原 MemGPT · ~25k★；活跃开发在 letta-code）

**写入**：记忆 = agent 自己维护的 md 文件仓库（MemFS，git 管理），agent 自主决定记什么并 commit。

**检索**：根索引常驻注入 system prompt，正文按需读取——**两级火箭**：路标常驻、正文拉取。默认无向量索引。

**遗忘**：git 版本史回滚；闲时后台 agent（dreaming）提炼更新；`/doctor` 记忆体检（重复/占位/层级审计）。

**部署**：npm 本地可跑，云为默认路径。

**注意**：它没有"不替记忆"约束（记忆本就是 agent 草稿）——**我们只偷机制（路标/体检/版本意识），不偷写权**。

## 3. Graphiti（getzep/graphiti · ~32k★ · 活跃）

**写入**：时序知识图谱，原子单位是**带有效期的事实三元组**，溯源到 episode。

**检索**：语义 + BM25 + 图遍历三路，亚秒级。

**遗忘**（本项目最锋利）：**事实有效期窗口——旧事实标记失效（invalidated）而非删除**，双时间轴（事实时间 vs 系统得知时间），可查任意时点。

**部署**：硬依赖图数据库（Neo4j 等）——与我们的本地铁律正面冲突。**借鉴止于数据结构**："取代而非删除 + 有效期"可直接搬进记忆索引字段。

## 4. Memobase（memodb-io/memobase · ~2.9k★ · **已停滞约 9 个月**，官方转向 Acontext）

**写入**：用户画像（可配置槽位）+ 事件时间线双层；对话先进 buffer 攒批（~1024 token 或空闲 1h）再 LLM 提炼——**不在热路径写记忆**，LLM 调用从 3-10 次压到 3 次。

**检索**：profile 全量直出（<100ms）；context API 直接打包 prompt 字符串，自带模板措辞：**"Unless the user has relevant queries, do not actively mention those memories"**——对陪伴/搭档场景极有参考价值。

**部署**：FastAPI+Postgres+Redis——超出本地铁律。只作设计参考，不作依赖。

## 5. Cognee（topoteretes/cognee · ~32k★ · 活跃）

**定位**：宣称 "Runs locally for free — no API key required"（八家唯一）。

**写入**：文本/代码入图；**session 教训经 `improve` 蒸馏进永久记忆**——会话经验与永久记忆分池晋级。

**降级设计**：无 LLM key 时用本地 GLiNER+嵌入模型，能力降级而非报错。

**部署**：Python 栈，本地模型需首次下载——"本地小模型"恰是我们禁的。**学它的分池晋级与降级思路**。

## 6. LangMem（langchain-ai/langmem · ~1.7k★ · 活跃）

**写入双模式**（官方明示权衡）：热路径（agent 对话中自主存）vs 后台（manager 会话外抽取合并）。

**借鉴**：对陪伴/搭档场景，写记忆不应打断对话——**后台批处理是对的**。

## 7. A-MEM（agiresearch/A-mem · ~1.2k★ · 研究代码）

**写入**：LLM 生成结构化笔记（描述/标签/关键词）；**入库时自动与相关旧记忆建双向链接**——记忆库从列表变成网。

**演化**：新笔记回溯刷新旧笔记的 tags/context。

**借鉴**：see-also 邻居表完全可以用关键词重合度在零依赖下做（小语料两两比对是毫秒级运算）。

## 8. HippoRAG 2（OSU-NLP-Group/HippoRAG · ~4.1k★ · 活跃）

**检索**：查询抽实体锚点后在图上跑 **Personalized PageRank 扩散**——多跳关联文档自然浮出，"联想回忆"的数学形式。

**借鉴**：小图上手写两轮扩散（命中节点给邻居分发一半权重）即可获得大部分收益。

## 横向对比

| 项目 | 写入策略 | 原子单位 | 检索方式 | 遗忘机制 | 部署依赖 |
|---|---|---|---|---|---|
| Mem0 | v3 ADD-only 只增不改 | 独立事实 | 语义+BM25+实体融合+时间推理 | 不删不改，检索时消解 | LLM+嵌入（硬） |
| Letta | agent 自主写文件并 commit | md 文件+路标索引 | 根索引常驻+按需读取 | git 回滚+dreaming+doctor | npm 可本地 |
| Graphiti | LLM 抽三元组入图 | 带有效期三元组 | 语义+BM25+图遍历 | **失效标记不删除**，双时间轴 | 图数据库（硬） |
| Memobase | buffer 批提炼 | profile 槽位+事件 | profile 直出+context API | 槽位覆盖 | Postgres+Redis |
| Cognee | 入图+session 晋级 | 实体/关系/chunk | 图/向量/代码路由 | 显式 forget；能力降级 | Python+本地模型 |
| LangMem | 热路径/后台双模 | Store 条目 | 向量检索 | 后台合并 | LLM+嵌入 |
| A-MEM | 结构化笔记+自动建链 | Zettelkasten 笔记 | 向量为主 | 记忆演化回溯刷新 | ChromaDB+LLM |
| HippoRAG 2 | OpenIE 三元组建图 | 实体+passage 节点 | PPR 扩散多跳 | 无 | LLM+嵌入 |

## 共性规律

1. 头部项目不约而同从"写入时智能改写"转向**只增不改 + 检索时消解**（Mem0 v3、Graphiti 失效标记）。
2. 检索层全部走向**多信号融合**——没有一家只靠单一信号。
3. "联想"成为新战场：建链、扩散、路标——benchmark 之外的"像人"体验来自网状关联。
4. 注入位置全部是 system prompt 拼接 + top_k 数量控制，无黑科技。

## 明确不学清单

- **向量检索/嵌入模型**：违反纯本地铁律；小语料规模下 BM25+关键词重合度已够。
- **图数据库**：依赖违规；邻接表+手写扩散已覆盖小图场景。
- **LLM 裁决改写记忆**：已被 Mem0 自己在 v3 否定，且违反"只浮线索"哲学。
- **agent 自主改写记忆**：哲学相反（它把记忆当草稿，我们当档案）——只偷机制不偷写权。
- **停更项目选型**（如 Memobase）：只作设计参考。
