# 操作手册

面向在一台机器上接入、调整和卸下对影的人。笔记留在那台机器上。操作时不要把对方的文件拷到自己的机器、网盘或聊天里。

## 在新机器上接上

把整个插件目录复制过去即可，不必用 Git，也没有单独的安装程序。目录里自带引擎。入口是 `mcp/server.mjs`。机器上需要 Node 18 或更高版本。

```text
<插件目录>/
  package.json
  engine/                  上浮与体检
  mcp/server.mjs           入口
  mcp/client.mcp.json      通用粘贴稿
  mcp/extensions.mjs       扩展位（向量与转换目前都是空）
  adapters/                拉取合约，以及本机目录这一种实现
  hooks/                   可选的上浮钩子
  examples/partner-xiaolin 虚构示例，可用来冒烟
```

可选的词法索引包不是运行所必需的。不装它时，检索走全量扫描。

打开 `mcp/client.mcp.json`，把里面的 `command`、`args`、`env` 贴进宿主的 MCP 设置。这是通用稿：不探测宿主，也不替任何一款前端改配置。某个具体前端的最终片段，等那个宿主有了名字再另写。

- `<插件目录>`：这份目录的绝对路径
- `<授权记忆根>`：允许读取的笔记目录。多个目录用英文分号隔开

保存后新开一轮对话。不经过宿主也可以冒烟：

```bash
node engine/surface.mjs "部署" --root examples/partner-xiaolin --json
```

结果里应出现 `会议纪要.md` 和 `决策记录.md`。

## 改授权根

改宿主环境里的 `DUIYING_ROOTS`，或在单次调用里传 `root`。只填写对方同意被检索的目录。改完新开对话。

上浮钩子若使用，根写在 `DUIYING_HOOK_ROOTS`（或该用户家目录的 `.duiying-hook-roots.json`）。钩子上的同步默认关闭。同步放到手动执行，或约定好的定时任务里，不要为了省事设 `DUIYING_HOOK_SYNC=1`。

## 从本机目录收进授权根

笔记若已经在授权根里，直接检索，不必再复制一份。

笔记若在另一个本机文件夹（共享目录，或一次导出目录），用内置适配器 `directory` 拉进授权根。它走通用的 `list` / `fetch` / `toNote` / `sync`，不绑定某一种共享协议。只收已经是 Markdown 的文件。源文件不改、不删。水位记在授权根的 `.duiying-company-sync.json`，按源文件的修改时间做增量：比水位更晚的修改会覆盖同一篇。

```bash
node hooks/company-sync.mjs
```

| 变量 | 作用 |
|---|---|
| `DUIYING_COMPANY_ADAPTER` | `directory` |
| `DUIYING_COMPANY_SOURCE` | 源目录 |
| `DUIYING_COMPANY_ROOT` | 授权记忆根 |
| `DUIYING_COMPANY_SYNC_STRICT` | 默认失败也以 0 退出。设为 `1` 时，失败才以非 0 退出 |

## 体检

```bash
node engine/surface.mjs --doctor --root <授权记忆根>
```

或调用 MCP 工具 `memory_doctor`。只出报告，不改文件。

## 沉默与取代

在笔记文首：

```markdown
---
suppress: true
suppress_when: [只在这些词下沉默]
superseded_by: 新的一篇.md
---
```

`suppress: true` 整篇不浮。`suppress_when` 只在查询含这些词时不浮。`superseded_by` 指向同一授权根里的相对路径，旧篇降权保留并附注。删掉这些行即恢复。读法见 [使用说明](使用说明.md)。

## 同步失败时

1. 看标准错误里的 `company-sync:` 一行。
2. 核对源目录还在、授权根可写、适配器名是 `directory`。
3. 源目录里的 Word、PDF、WPS 不会被转换。这一版跳过它们，只有 `.md` 会进来。这不是故障。
4. 失败不应挡住上浮。用授权根直接跑一句上浮，确认已经收进来的笔记还在。
5. 水位文件若损坏，同步会停下来并且不再继续写入。把授权根里的 `.duiying-company-sync.json` 移走后再跑；已经写好的笔记还在。不要去改源目录。

## 升级

用新的插件目录换下旧的插件目录，保留宿主里的授权根配置。不要覆盖授权根里的笔记。版本以目录里的 `package.json` 为准。这一版是 0.4.0。

## 卸下并清掉生成物

1. 从宿主的 MCP 设置里去掉这条命令。
2. 删除插件目录。
3. 生成的词法索引在各授权根下的 `.duiying/`。不需要时删掉这个目录。同步水位是同一根里的 `.duiying-company-sync.json`，不需要同步时可以删。你另存的日志一并删掉。
4. 不要删除对方的笔记，除非对方明确要求。不要把这些文件拷离这台机器。

## 预留位（这一版没有接上）

| 位置 | 现在 | 以后若接上 |
|---|---|---|
| `engine/candidate-recall.mjs` | 词法候选召回的入口。当前可选后端文件是 `engine/recall-minisearch.mjs`。没装该包就全量扫描 | 只替换这一层。排序、门控、沉默、取代仍在原引擎 |
| `vectorCandidateSource` | 固定为空。MCP 扩展里也是空 | 仍从召回这一层并入候选。这一版没有向量 |
| `adapters/extensions.mjs` 的 `markdownConverter` | 空。非 Markdown 跳过 | 纯本地、离线的函数把源文件变成 Markdown，结果写入授权根，不改原文件 |
| `list` / `fetch` / `toNote` / `sync` | `directory` 是其中一种实现 | 另一种来源以后按同一组方法加一个文件，不改引擎 |

## 练习题的跑法

题单放在本机，不要提交进仓库。一次练习用 20 到 30 题。每题写明查询，以及期望命中哪一个文件，或期望说明没有命中。

```bash
node scripts/acceptance-dry-run.mjs --questions <本地题单.json> --root <授权记忆根> --out <报告.json>
```

题单形状：

```json
{
  "questions": [
    { "id": "1", "query": "一个能对上的词", "expect": "hit", "path": "某篇.md" },
    { "id": "2", "query": "no-such-token", "expect": "miss" }
  ]
}
```

`hit` 要通过，结果里得出现 `path`。`miss` 要通过，结果必须是空的，报告里记「没有命中的记忆。」退出码 0 表示这一份题单全部通过。仓库里不放题库。
