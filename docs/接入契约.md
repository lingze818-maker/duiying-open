# 前端接入契约

对影记忆上浮引擎是**前端无关**的：任何能发起子进程调用或跑 Node 代码的
AI 前端，三分钟接入。契约只有两条铁律：

1. **只消费线索**：引擎返回的是"可能相关的记忆路标"，如何注入、是否提及，由前端与用户的关系决定；
2. **不改写记忆**：前端不回写、不修改记忆原文——要更新记忆，让用户改文件或加 frontmatter 状态标记。

---

## 方式 A · CLI 直调（zcode / codex / deepseek harness 等 agent 环境）

在 agent 的工具定义里包一层：

```json
{
  "name": "memory_surface",
  "description": "从长期记忆库检索相关记忆线索。用户提到过去的决定/事件/偏好时调用。",
  "command": "node /path/to/duiying-open/engine/surface.mjs \"$QUERY\" --root /path/to/memory --json"
}
```

消费规则（写进 agent 的 system prompt）：

> 工具返回 `results` 是记忆线索（一行一条）。除非用户问起或话题自然相关，
> **不要主动罗列这些记忆**；引用时说明"我记得，[日期] 你决定过…"，并给出出处文件。

### 参数速查

| 参数 | 说明 |
|---|---|
| `"关键词1,关键词2"` | 位置参数，逗号分隔；含"最近/上周/去年"等词自动切时间优先模式 |
| `--root <目录>`（可重复） | 语料根目录，扫描全部 `.md`；缺省当前目录 |
| `--json` | JSON 输出（程序消费推荐） |
| `--detail` | 附正文命中摘录 |
| `--no-links` | 关闭联想扩散（对照调试） |
| `--limit N` | 最多返回 N 条（默认 10） |
| `--out <文件>` | 把本次输出写入文件；与 `--json` 合用时写入 JSON，提示走 stderr |
| `--exclude <目录名>`（可重复） | 按目录名额外跳过。默认已跳过 `node_modules`、`.git`、`build`、`dist` 等 |
| `--doctor` | 记忆库体检模式（不需要关键词） |
| `--gate` / `--no-gate` | 自动上浮门控。**手敲 CLI 默认关**（你点名要查就查）。`--gate` 才按问候 / 纯情绪 / 无话题 / 短时重复拦截。环境变量 `DUIYING_GATE=1` 或 `0` 改默认，命令行旗标优先 |
| `--rerank` / `--no-rerank` | 词面重排，默认开。多条命中且重合度不同时，用 token 重合 + 子串加分微调顺序。`DUIYING_RERANK=0` 可关 |

## 方式 B · JSON 契约（程序消费）

```jsonc
{
  "engine": "duiying-open/0.2",
  "query": ["部署", "回滚"],
  "total": 3,
  "hint": "除非对方问起或自然相关，不要主动罗列这些记忆。",
  "results": [
    {
      "path": "决策记录.md",       // 相对该条 root 的路径（单根时即 --root）
      "root": "/path/to/memory",   // 仅多个 --root 时出现：解析后的语料根（正斜杠）
      "title": "项目决策记录",      // 首个 # 标题，路标用
      "date": "2026-03-15",        // 记忆发生日：frontmatter date（YYYY-MM-DD）；没有则是 mtime 的本地日历日（不是 UTC）
      "score": 12.3,               // 融合分（含时间先验与联想扩散）。多条命中且词面重合不同时，默认再并进词面分，仍是这个量级。不要只按它重排：词面命中整体在纯联想之前
      "links": ["会议纪要.md"],    // 联想邻居（see-also），相对该条 root
      "note": "此条已被取代，见 新方案.md",  // 仅 superseded_by 条目有
      "excerpt": "部署用 Docker Compose…"    // 仅 --detail 时有
    }
  ],
  "gate": {                        // 仅打开门控时有。手敲 CLI 默认没有这个字段
    "enabled": true,
    "allow": true,                 // false：没检索，results 为空
    "intent": "memory_recall",     // memory_recall | open_chat | companion
    "reason": "memory"             // greeting | emotion | companion | open_chat | memory | topic | duplicate | no_anchor
  }
}
```

注入模板建议（两段式，控制 token）：

```
[长期记忆线索]（除非用户问起，不要主动罗列）
- [2026-03-15] 项目决策记录 —— 决策记录.md
  此条已被取代，见 新方案.md
```

需要展开某条时，由前端按 `path` 读原文；多个 `--root` 时读该条 `root` 下的 `path`。**引擎不把整篇原文塞进结果**（`--detail` 只给一行摘录）。

多个 `--root` 一起查时，每条结果多一个 `root`。`path` 和 `links` 都相对这条的 `root`，不要只凭文件名打开。只查一个根时没有 `root` 字段。`superseded_by` 与近重复降噪只在同一个根里比较：A 库的附注不会指向 B 库的文件，B 库也不会因为正文和 A 库相近就被丢掉。

排序：先列出查询词真正出现过的条目（标题、文件名或正文），再列出仅因联想带出的邻居。联想仍然会上浮，但不会盖过直接命中。

## 方式 C · Node 程序内嵌

```js
import { tokenize, buildStats, bm25, buildLinks, spread } from "duiying-open/engine/lib.mjs";

// 纯函数、无 IO：索引和打分的数据全在参数里，编排方式随你
const docs = myLoader();                 // [{ tf: Map, len }]
const stats = buildStats(docs);
const scores = docs.map(d => bm25(tokenize("部署"), d, stats));
const links = buildLinks(docs.map(d => new Set(d.tf.keys())));
spread(scores, links);                   // 联想扩散，两轮
```

## 方式 D · MCP server（zcode / claude 系 / 任何 MCP 宿主）

```bash
# 先本机试一下协议（应返回两个工具名）
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05"}}
{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | node mcp/server.mjs
```

zcode 的 MCP 配置（`~/.zcode/cli/config.json` 的 `mcp.servers`）：

```json
{
  "duiying-memory": {
    "command": "node",
    "args": ["/path/to/duiying-open/mcp/server.mjs"],
    "env": { "DUIYING_ROOTS": "D:/你的记忆库;D:/另一个库" }
  }
}
```

配置后新开会话即获得 `memory_surface`（检索线索）、`memory_doctor`（体检）
与 `memory_ingest`（写入贡献）三个工具——AI 会在你提到过去的决定/事件/偏好时自动调用，
也可以主动把这段对话里值得留下的内容写进库。`DUIYING_ROOTS` 用分号分隔多个语料根；工具参数 `root` 可逐次覆盖。

## 多前端写入（memory_ingest）

任何接 MCP 的前端都可以向共享库贡献记忆——摘要由写入方负责（谁灌的谁写），
原文两种形态二选一：**落盘灌库**（content 进库）或**路径标记**（source_path 指向原处，库只落薄条目）。

MCP 调用参数：

| 参数 | 说明 |
|---|---|
| `summary`（必填） | 记忆摘要，写入方负责；超 40 字自动截标题、全文保留正文 |
| `channel`（必填） | 来源前端标识（`zcode` / `codex` / `qq-bridge`…自由打），落为子目录与 frontmatter |
| `content` / `source_path` | 二选一：落盘灌库 / 路径标记 |
| `event`（可选） | 事件标签（`decision` / `meeting` / `insight` / `milestone`…自由打） |

CLI 侧等价入口：`node engine/ingest.mjs`（同参数，脚本化批量灌库用）。

写入位置 `<root>/ingest/<channel>/<日期>-<slug>.md`，append-only（不覆盖已有，slug 冲突自动递增）。
检索默认全库融合——联想扩散跨 channel 跑：在 A 前端拍的板，能被 B 前端的对话勾出来。
换前端 = 配一行 MCP，吸入全库、可呼出贡献——呼吸而已。

## 上浮的触发层级（自动化程度由你决定）

MCP 工具是被动协议：引擎不会自己跑，等宿主来调。**记忆的"自然而然"分三级，
取决于你的前端愿意做到哪一层——引擎只保证：任何时候被问到，都答得好。**

### 层级一 · 约定式（推荐基线，零代码）

在前端 AI 的系统提示/岗位书里加一句约定：

> 每轮对话开始时，先用用户的消息作为 query 调用 `memory_surface`，命中的线索自然引用，除非用户问起不要罗列。

任何能调 MCP 的前端立刻获得"自动上浮"体验——AI 每轮睁眼先翻一遍记忆再说话。
成本：每轮一次工具调用。

### 层级二 · 注入式（hook / 中间件，零主动调用）

若你的前端支持"用户消息钩子"（如 Claude Code 的 `UserPromptSubmit` hooks、
OpenAI 系的 middleware），挂一个管线：每条用户消息进模型前，自动跑
`node engine/surface.mjs "<用户消息>" --root <库> --json --limit 5`，
把命中的路标注入本轮上下文。仓库自带的 `hooks/user-prompt-surface.mjs`
已经这样做，并且**默认打开门控**（见下节）：问候和纯情绪不会往上下文里塞记忆。
自建管线若也是每条消息都跑，加上 `--gate`。

AI 睁眼即带记忆，不需要任何工具调用。成本：每条消息一次引擎调用（毫秒级，纯本地）。

### 层级三 · 内建式（自建前端的完全体）

前端自己在服务端实现检索管线——对影主服务的 wake 契约就是这么做的：
每轮对话，服务端先检索、把命中的路标与时间锚组装进 system_prompt，然后 AI 才开口。
适合自建 UI / 长期陪伴场景，检索策略可以按你的关系自定义。

### 怎么选

| 你的前端 | 建议 |
|---|---|
| 能调 MCP 的现成工具（Claude Code / zcode / …） | 层级一：系统提示加一句话 |
| 支持 hooks 或 middleware 的前端 | 层级二：注入管线 |
| 自建 UI / 长期陪伴 | 层级三：服务端内建 |

三层可以共存：层级一保证下限，层级二/三往上加。

## 自动上浮门控，和手敲检索不是一回事

门控只拦**自动注入**。你自己敲的

```bash
node engine/surface.mjs "最近" --root examples/partner-xiaolin --json
```

默认照旧去搜。只含时间词时现在仍是空结果——门控不替它把最近的笔记列出来。

| 入口 | 默认 | 怎么改 |
|---|---|---|
| CLI `node engine/surface.mjs` | 关 | `--gate` 打开；`--no-gate` 强制关 |
| 钩子 `hooks/user-prompt-surface.mjs` | 开 | `DUIYING_GATE=0` |
| MCP `memory_surface` | 关（模型主动来查） | 参数 `gate: true`，或把 MCP 当成每轮预取时设 `DUIYING_GATE=1` |

规则只有三档，全是正则，没有模型：

- `memory_recall`：有回忆信号（记得、上次、以前、remember、last time …），或去掉问候、泛情绪和光秃时间词之后还剩一个具体话题。自动上浮会检索。
- `companion`：整句就是问候、纯情绪（「好累」）、或很短的附和。不检索。
- `open_chat`：更长、但没有回忆信号也没有话题。不检索。

拦住时 `total` 为 0，`results` 为空，`gate.allow` 为 false，**语料不会被扫**。泛情绪词会从自动上浮的锚点里拿掉：「好累，记得上次部署」只拿「记得上次部署」去对。

同一进程里，同一句若刚刚浮出过至少一条，120 秒内再来直接空（`gate.reason = duplicate`）。间隔用 `DUIYING_GATE_TTL_MS` 改。钩子每次是新进程，不跨消息去重；MCP 常驻进程和程序里自己传入的 `gateSession` 才会记住。

词面重排默认开，和门控各自独立：`--no-rerank`、MCP `rerank: false`、`DUIYING_RERANK=0` 都关掉。多条命中而且 token 重合度不一样时，重合更高的排前面，分数仍和原来的融合分同一量级。重合度一样（例如都只是命中「部署」）时，顺序和分数都不变。

## 与私有对影对齐的公开能力

上面两件事——**上浮门控**和**词面重排**——是私有对影里可以公开的规则：表面门控、词面重合（token 重合 + 子串加分）、以及规则优先的三种意图。开源版只搬了这些。

不在这个仓库里的：陪伴场景的情绪安抚和关系拦截、私有档案、任何真实对话。没有角色设定，也没有私有记忆库。向量重排不在默认路径上，运行时仍然零依赖。

## 记忆条目状态（frontmatter）

```markdown
---
title: 自定义路标标题            # 可选：覆盖首个 # 标题
date: 2026-04-10                # 可选：这件事发生的日子。时间先验、时间优先和结果 date 用它；没有再退回文件修改时间
superseded_by: 新方案.md        # ⑥ 已被取代：降权保留 + 附注指向
suppress: true                  # ⑦ 整篇沉默：文件原样保留，检索剔除
suppress_when: [裁员, 事故]     # ⑦ 条件沉默：查询含这些词时不浮
---

# 正文照常写
```

`date` 必须是真实的 `YYYY-MM-DD`（本地日历日，不带时间）。写了别的格式、或没写这个字段，时间先验和结果里的 `date` 都退回文件 mtime 的本地日历日。引擎不根据正文日期改写文件。

## 体检

```bash
node engine/surface.mjs --doctor --root /path/to/memory
```

五项检查：`broken_link`（状态指向不存在的文件）/ `near_duplicate`（重合度 ≥75%）/
`title_quality`（无标题或超 40 字）/ `suppressed_list`（沉默中的篇目提醒定期复核）/
`missing_date`（正文里有 `YYYY-MM-DD`，但没有合法的 `date` 字段；或 `date` 不是这一格式。只提示，不改文件）。
坏链和近重复都只在同一个根里判断。多个 `--root` 时，报告里的 `file`（以及近重复对照的文件名）写成「根目录/相对路径」，不会出现两个无法区分的 `note.md`。
体检报告供人工深度清理；日常检索已自动应用安全降噪（近重复只浮发生日较新的一条，没有 `date` 时比较 mtime；坏链附注静默降级）——文件永远不被修改。
