## 0. 目标与非目标

**目标**：给 duiying-open 引擎加「语义向量检索」一路，与现有 BM25 词面一路并行融合，使「意思相近但用词不同」的记忆可被召回（如搜「服务器宕机」命中写着「服务中断」的纪要），同时**不破坏现有任何行为**。

**非目标（本期不做）**：多语言检索、图像向量、分布式、增量重训。权限/审计是 M2。

## 1. 核心架构决策：可插拔 embedding 后端（选型 C）

对影的立项哲学是「**本地零依赖**」——这是它对企业隐私场景最大的卖点，**不能为向量破坏**。因此：

```
embedding 后端 = 可选模块（三种形态，按环境自动选择或配置指定）
  A. transformers.js（默认推荐）：Node 原生跑 ONNX 模型
     - 模型：BGE-small-zh-v1.5 ONNX 版（~90MB，中文效果最好的小杯）
     - 依赖：@huggingface/transformers（可选依赖，不装不影响词面检索）
  B. Python 伴生：sentence-transformers + BGE（若部署机已有 Python 环境且要大杯模型）
     - 通过子进程 stdio JSON 协议调用（与 daogang 的 dsh-load 模式同构）
  C. 无后端（现状）：embedding 不可用时，向量路静默关闭，纯词面照常工作
```

**铁律：三形态下 API 行为完全一致。**装不装模型，`search()` 的调用方式零变化——这是「零依赖」哲学的工程化表达，也是体制内客户「不开外网也能跑」的前提（模型文件随安装包离线分发）。

## 2. 向量存储：拒绝重型向量库

规模判断：企业单部门记忆库 **1万~10万条** 量级。这个规模：

- **不需要** FAISS/Milvus/qdrant（杀鸡用牛刀，还引入服务进程）
- **用**本地二进制文件（Float32Array 平铺 + 元数据 JSONL），检索用暴力内积/余弦
- 算账：10 万条 × 512 维 Float32 = 200MB 内存，暴力余弦一次 ~50ms（Node 单线程）——**完全可接受**
- 索引文件分根存储（复用现有 per-root 结构），增量追加，定期重建

### 2.1 扩展空间预留（大型客户冗余冗量要求）

**本期默认后端只服务 10 万条级，但存储层从第一天就是接口抽象，不是具体实现**：

```
VectorStore 接口（M1.1 落地）：
  upsert(items) / search(vec, topK) / remove(ids) / rebuild() / stats()
  后端实现 = local-file（本期默认）| 未来可插拔
```

- **规模分层触发线**（写进代码常量与文档）：单根 ≤10 万条用 local-file 暴力检索；超过时日志提示升级后端，**不自动降级功能**
- **预留后端位**（接口已按其需求设计，实现随客户需求排期）：
  - `sqlite-vec`（同进程嵌入式，百万级，仍是单文件零服务——优先候选）
  - HNSW 类本地索引（千万级内存换速度）
  - 外部向量库（Milvus/Qdrant 私有化集群——大型公司多部门共享池场景，部署形态不同但接口相同）
- **维度不写死**：配置项 `embedding.dim`，后端按维度自适应——换模型不改存储代码
- 检索调用方永远只面向 `VectorStore` 接口，**任何代码不得直接触碰 local-file 实现的内部结构**（review 硬性检查项）

未来若规模到百万级，再换 sqlite-vec 或 HNSW——接口留抽象层，本期不预支复杂度。

## 3. 双路融合排序

```
score_final = w_lex * score_lex_normalized + w_vec * score_vec_normalized
默认权重：w_lex = 0.4，w_vec = 0.6（语义检索时代码/名词类词面权重应更高，待冻结评测集调参）
```

- 两路各自 max-normalize 后加权融合（沿用现有「标题/BM25/短语」的归一化融合模式，工程一致性）
- **向量命中不带 note 伪装成词面命中**：结果新增 `match: "lexical" | "semantic" | "both"` 字段，透明告知命中来源（评测岗的职业习惯：不给用户不可解释的排序）
- 时间先验、单字回退、同义词扩展照旧工作——单字回退只在**两路都零分**时作为最后兜底（现状行为不变）

## 4. 索引与失效

- 记忆写入/修改时同步更新该文件的向量（写索引与词法索引同钩子）
- embedding 计算失败的文件：标记 `vec_missing`，检索时该文件只走词面路——**部分失败不阻塞整体**
- 模型更换（换 embedding 模型）→ 向量维度/空间变化 → 全量重建索引（提供 `--rebuild-vec` 命令）

## 7. 风险与开放问题

- **模型体积**：90MB 模型随安装包分发可接受；若客户嫌大，B 后端换 bge-large（更准但 300MB+）是配置项不是代码变更
- **信创 CPU**：transformers.js 走 WASM/WebGPU，鲲鹏（ARM）兼容性需实测——M3 部署阶段的验证项，设计上已把「后端可替换」留好
- **开放问题**：embedding 维度要不要进 note 展示给用户？（初步：不展示，属于实现细节）
